# 🐧 Linux 系统管理期末复习重点

## 1. 基础文件与目录操作
- **进入上一级目录**
  - 命令：`cd ..`
- **查看内容但不打开编辑器**
  - 命令：`cat filename.txt`
  - *注意：不能对目录使用 cat 命令。*
- **赋予脚本执行权限**
  - 命令：`chmod +x script.sh`

## 2. 用户与组管理
- **创建用户并指定 UID 和组**
  - 命令：`useradd -u 1500 -G wheel tom`
  - **参数解析**：
    - `-u 1500`：指定 UID。
    - `-G wheel`：指定**附加组** (Supplementary Group)。*注意：原笔记 "whell" 拼写错误。*
    - `-g`：用于指定**主组** (Primary Group)。
- **用户认证日志**
  - 位置：通常记录在 `/var/log/secure` (RHEL/CentOS) 或 `/var/log/auth.log` (Debian/Ubuntu)。
  - *注意：原笔记 "i昂管" 为 "相关" 的拼写错误。*

## 3. 网络配置与管理
- **监控网络连接**
  - 命令：`netstat`
  - 功能：监控网络连接、路由表、接口统计信息等。
- **查看/配置网卡信息**
  - 命令：`ifconfig`
- **关键配置文件 (易混淆考点)**
  - `/etc/hosts`：用于储存 **IP 与主机名** 的静态映射关系。
  - `/etc/resolv.conf`：用于储存 **DNS 服务器** 的 IP 地址。
- **虚拟机网络模式**
  - **Bridged (桥接模式)**：让虚拟机获得独立 MAC 地址并直接参与物理局域网。

## 4. Vim 编辑器模式
- **三种基本模式**：
  1. **普通模式 (Normal Mode)**：默认进入，用于导航和删除。
  2. **插入模式 (Insert Mode)**：普通模式下按 `i` 进入，用于打字。
  3. **命令行模式 (Command-line Mode)**：普通模式下按 `:` (冒号) 进入，用于保存退出 (`wq`)。

## 5. Syslog 日志优先级 (Severity Levels)
> **核心原则**：数值越**小**，优先级越**高** (越严重)。

| 数值 | 关键词 | 含义 |
| :--- | :--- | :--- |
| 0 | emerg | 紧急 (系统不可用) |
| ... | ... | ... |
| 3 | err | 错误 |
| 4 | warning| 警告 |
| ... | ... | ... |
| 6 | info | 一般信息 |
| 7 | debug | 调试信息 |

- **考点纠错**：
  - “数值小于 info (6) 的是 debug” —— **错误**。Debug 是 7，数值比 info 大。数值小于 6 的是 notice, warning, err 等更严重的级别。
  - “warning 的等级低于 err” —— **正确**。Warning (4) 的严重性确实低于 Error (3)。

# Linux chown 命令详解

`chown` (Change Owner) 主要用于修改文件或目录的**所有者**和**所属组**。

在 Linux 权限管理中，它通常与 `chmod` 配合使用：`chown` 决定“谁是主人”，`chmod` 决定“主人能做什么”。

## 1. 核心语法

```bash
chown [选项] [所有者]:[所属组] 文件或目录
```

* **所有者 (User)**: 文件的拥有者账号。
* **所属组 (Group)**: 文件所属的用户组。
* **分隔符**: 使用冒号 `:` (推荐) 或点 `.` (旧式写法，不推荐) 分隔。

## 2. 实战场景详解

### 场景 1：仅修改所有者

这是最常用的用法。例如，把 `file.txt` 的主人从 `root` 改为 `jerry`。

```bash
# 语法：chown [用户] [文件]
sudo chown jerry file.txt
```

### 场景 2：同时修改所有者和所属组

通常在部署网站或迁移数据时使用。例如，把 `web` 目录给 `www-data` 用户和 `www-data` 组。

```bash
# 语法：chown [用户]:[组] [文件]
sudo chown www-data:www-data /var/www/html/index.php
```

### 场景 3：仅修改所属组

虽然有 `chgrp` 命令专门做这个，但 `chown` 也能做。只要在冒号前留空即可。

```bash
# 语法：chown :[组] [文件]
# 把 file.txt 的组改为 docker
sudo chown :docker file.txt
```

### 场景 4：自动继承该用户的主组

如果你只指定了用户，并在后面加了一个冒号，`chown` 会自动将组也改为该用户的默认主组（Login Group）。

```bash
# 假设 jerry 的主组也是 jerry
sudo chown jerry: file.txt
# 结果：所有者变为 jerry，所属组也变为 jerry
```

## 3. 递归修改 (-R)

与 `chmod` 一样，如果你要修改一个目录及其内部**所有**文件和子目录的归属，必须加 `-R`。

```bash
# 将整个 project 目录归属给 tom
sudo chown -R tom:dev_team /opt/project
```

> **⚠️ 高危警告**：在使用 `chown -R` 时，务必检查路径！
> 比如 `chown -R user:group /` 会导致整个系统崩溃（SSH失效、sudo失效等），通常只能重装系统解决。

## 4. 常见问题 (FAQ)

### Q1: 为什么我修改文件需要 sudo？

**答**：出于安全考虑，普通用户通常**不能**将自己的文件“送”给别人（改为别人的名字），也不能把别人的文件“抢”过来。因此，`chown` 几乎总是需要 `root` 权限 (sudo)。

### Q2: chown 和 chmod 的区别？

* **chown** (Change Owner): 改变文件的**归属权**（这是谁的？）。
* **chmod** (Change Mode): 改变文件的**访问权限**（能读吗？能写吗？）。

### Q3: 这两个命令应该先执行哪个？

通常建议 **先 chown，后 chmod**。
因为如果先设置了 `700` (仅所有者可读写)，然后你用 `chown` 把所有者换成了别人，那你自己可能瞬间就失去对该文件的控制权了。

## 5. 总结速查表

| 目的 | 命令示例 | 含义 |
| :--- | :--- | :--- |
| **只改主人** | `chown jerry file` | 主人变 jerry，组不变 |
| **改主人和组** | `chown jerry:dev file` | 主人变 jerry，组变 dev |
| **只改组** | `chown :dev file` | 主人不变，组变 dev (同 `chgrp`) |
| **递归修改** | `chown -R jerry:dev dir/` | 修改目录及内部所有文件 |
| **改回 root** | `chown root:root file` | 恢复为 root 所有 |

# Linux 权限与 chmod 命令详解

在 Linux 系统中，一切皆文件。为了保证安全性，系统对每个文件和目录都设定了访问权限。`chmod` (Change Mode) 命令就是用来修改这些权限的。

## 1. 权限的基础概念

当你在终端输入 `ls -l` 查看文件列表时，会看到类似这样的输出：

```bash
-rwxr-xr--  1 user group  4096 Jan 01 12:00 myfile.txt
drwxr-xr-x  2 user group  4096 Jan 01 12:00 myfolder
```

### 1.1 第一列含义分解 (图解)

这一串字符（如 `-rwxr-xr--`）共 10 位。我们可以将其拆解如下：

```text
  -   rwx   r-x   r--
 [1]  [2]   [3]   [4]
```

这 4 个部分分别为：

1.  **第 1 位 ([1])**：文件类型
    * `-`：普通文件
    * `d`：目录 (Directory)
    * `l`：软链接 (Link)

2.  **接下来的 9 位 ([2]-[4])**：权限位，每 3 位一组，分别对应不同的用户身份。

| 标记 | 组别 | 英文 | 简写 | 含义 |
| :--- | :--- | :--- | :--- | :--- |
| **[2]** | **第 1 组** | **User** | **u** | **所有者**（创建该文件的用户）的权限 |
| **[3]** | **第 2 组** | **Group** | **g** | **所属组**（与文件属于同一用户组）的权限 |
| **[4]** | **第 3 组** | **Others** | **o** | **其他人**（既不是所有者，也不在同组）的权限 |

### 1.2 r、w、x 的具体含义

权限分为三种：读 (Read)、写 (Write)、执行 (Execute)。**注意目录权限的特殊性。**

| 权限 | 符号 | 对文件的含义 | 对目录的含义 (重要) |
| :---: | :---: | :--- | :--- |
| **读** | **r** | 可以查看文件内容 (cat, vim) | 可以列出目录中的内容 (ls) |
| **写** | **w** | 可以修改文件内容 | **可以在目录中创建、删除、重命名文件** |
| **执行** | **x** | 可以运行该文件 (如果是脚本/程序) | **可以进入该目录 (cd)**，且能读取文件元数据 |
| **无** | **-** | 无此权限 | 无此权限 |

---

## 2. 数字表示法 (八进制)

这是 `chmod` 最常用的方式，因为它简洁。我们将 `r`, `w`, `x` 转换为数字：

* **r (Read) = 4**
* **w (Write) = 2**
* **x (Execute) = 1**
* **- (无权限) = 0**

### 2.1 权限计算公式
每组权限的数字是其包含权限之和。

| 组合 | 计算 | 数字 | 含义 |
| :--- | :--- | :--- | :--- |
| `rwx` | 4 + 2 + 1 | **7** | 读、写、执行（最高权限） |
| `rw-` | 4 + 2 + 0 | **6** | 读、写（常用与普通文件） |
| `r-x` | 4 + 0 + 1 | **5** | 读、执行（常用于公开脚本/目录） |
| `r--` | 4 + 0 + 0 | **4** | 只读 |
| `-wx` | 0 + 2 + 1 | **3** | 写、执行（极少用） |
| `-w-` | 0 + 2 + 0 | **2** | 只写（极少用） |
| `--x` | 0 + 0 + 1 | **1** | 只执行 |
| `---` | 0 + 0 + 0 | **0** | 无任何权限 |

### 2.2 常见组合示例

* **`chmod 777 file`**: 任何人都有最高权限（**极度危险，慎用**）。
    * User(7) + Group(7) + Others(7)
* **`chmod 755 file`**: 所有者有全部权限，其他人只能读和执行（常见于程序、脚本、Web目录）。
    * User(7) + Group(5) + Others(5)
* **`chmod 644 file`**: 所有者可读写，其他人只读（常见于配置文件、网页文件）。
    * User(6) + Group(4) + Others(4)
* **`chmod 600 file`**: 只有所有者可读写，其他人无权访问（常见于 SSH 密钥 `id_rsa`、敏感数据）。
    * User(6) + Group(0) + Others(0)

---

## 3. 符号表示法 (字母操作)

除了数字，也可以用直观的字母来修改权限。

**语法**: `chmod [用户][操作][权限] 文件名`

* **用户**: `u` (User), `g` (Group), `o` (Others), `a` (All, 所有人)
* **操作**: `+` (增加), `-` (移除), `=` (设定为)
* **权限**: `r`, `w`, `x`

### 示例

```bash
# 给所有者增加执行权限
chmod u+x script.sh

# 给所属组和其他人移除写权限
chmod go-w file.txt

# 给所有人增加读权限 (等同于 chmod a+r file.txt)
chmod +r file.txt

# 强制设定所有者为读写，其他人为只读 (不理会之前的权限)
chmod u=rw,go=r file.txt
```

---

## 4. 常用参数：递归修改 (-R)

如果你想修改一个目录以及它里面**所有的**文件和子目录的权限，必须加上 `-R` (Recursive) 参数。

```bash
# 将 /var/www/html 目录下的所有文件权限改为 755
chmod -R 755 /var/www/html
```

> **⚠️ 警告**：使用 `-R` 时请务必小心。如果误对根目录 `/` 或系统目录使用了 `-R 777`，可能会导致系统崩溃或无法启动。

---

## 5. 总结速查表

| 常用数字 | 对应字符 | 适用场景 |
| :--- | :--- | :--- |
| **777** | `rwxrwxrwx` | 测试用，**极不安全**，任何人都可改可删 |
| **755** | `rwxr-xr-x` | 脚本、可执行程序、目录的标准权限 |
| **700** | `rwx------` | 仅自己可用的私密目录或脚本 |
| **666** | `rw-rw-rw-` | 所有人可读写的文件 (少用，有风险) |
| **644** | `rw-r--r--` | 配置文件的标准权限，防篡改 |
| **600** | `rw-------` | 个人隐私文件 (如 SSH 私钥) |

# Linux 特殊权限详解 (SUID, SGID, Sticky Bit)

在基础的 `rwx` (读写执行) 之外，Linux 还有 3 个特殊权限。这就解释了为什么有时你会看到 `chmod 4755` 这样由 **4位数字** 组成的命令。

## 1. 第 1 位数字的含义

当权限是 4 位数字时（如 `4755`），**第 1 位**代表特殊权限，后 3 位才是普通的 User/Group/Others 权限。

| 数字 | 英文缩写 | 全称 | 作用对象 | 核心作用 |
| :--- | :--- | :--- | :--- | :--- |
| **4** | **SUID** | Set UID | 二进制文件 | **以文件所有者的身份运行**，而不是运行者的身份 |
| **2** | **SGID** | Set GID | 目录 或 文件 | **在目录下创建的文件自动继承该目录的组** |
| **1** | **SBIT** | Sticky Bit | 目录 | **目录里的文件，只有创建者自己能删** |

---

## 2. SUID (Set UID) - 数字 4

这是最危险也是最强大的权限。

* **表现形式**：User 组的 `x` 变为 **`s`** (如 `-rwsr-xr-x`)。
* **经典案例**：`passwd` 命令。
    * 普通用户无法修改 `/etc/shadow` (密码文件)，但通过运行 `passwd` 命令却能修改密码。
    * 原因就是 `/usr/bin/passwd` 设置了 SUID。当你运行它时，系统会暂时把你当成 `root` (文件的所有者) 对待。

### 解析 chmod 4755
```bash
chmod 4755 myfile
```
* **4**: 开启 SUID。
* **755**: 所有者 rwx，组 rx，其他人 rx。
* **效果**: 任何用户执行 `myfile` 时，都会获得该文件所有者（通常是 root）的权限。

> **⚠️ 警告**：千万不要给 `vim`, `cat`, `bash` 等编辑器或 Shell 设置 SUID！否则普通用户可以用它去编辑 `/etc/passwd`，直接把自己变成 root。

---

## 3. SGID (Set GID) - 数字 2

主要用于团队协作的共享目录。

* **表现形式**：Group 组的 `x` 变为 **`s`** (如 `drwxr-sr-x`)。
* **作用**：如果不设 SGID，用户 A 在共享目录建立文件，文件的组是 A 的主组。设了 SGID 后，**文件的组会自动变成该目录所属的组**。
* **场景**：开发组 `dev` 有一个共享目录 `/project`。设置 SGID 后，组员 jerry 创建的文件，组会自动设为 `dev`，这样组员 tom 也能修改它。

```bash
# 给目录设置 SGID
chmod 2775 /opt/project
```

---

## 4. Sticky Bit (粘滞位) - 数字 1

主要用于公共临时目录。

* **表现形式**：Others 组的 `x` 变为 **`t`** (如 `drwxrwxrwt`)。
* **经典案例**：`/tmp` 目录。
* **作用**：`/tmp` 目录权限通常是 `777`（谁都能写）。但有了 Sticky Bit，**用户 A 只能删除自己创建的文件**，不能删除用户 B 的文件，即使原本的权限允许写入/删除。

```bash
# 给目录设置 Sticky Bit
chmod 1777 /public/tmp
```

## 5. 总结

回到你的问题，`chmod 4755` 的意思是：
1.  **755**: 这是一个可执行程序，谁都能运行。
2.  **4 (SUID)**: **但是**，运行时会自动获得该文件**所有者**的特权（如果所有者是 root，那就是获得 root 特权）。

| 特殊位 | 字母标志 | 常见位置 | 记忆口诀 |
| :--- | :--- | :--- | :--- |
| **4** (SUID) | `s` (在User位) | `/usr/bin/passwd` | **变身卡** (运行时变身成主人) |
| **2** (SGID) | `s` (在Group位) | 团队共享目录 | **继承卡** (子文件继承父目录的组) |
| **1** (SBIT) | `t` (在Other位) | `/tmp` | **保护卡** (防止别人删我的文件) |

# Linux tar 命令全攻略

`tar` (Tape Archive) 是 Linux 系统中标准的归档工具。它的主要作用是将多个文件或目录打包成一个文件（归档），并通常结合压缩工具（如 `gzip`, `bzip2`）来减小文件体积。

## 1. 核心参数详解 (必记)

为了方便记忆，我们将参数分为三类：**动作**、**属性**和**格式**。

### 动作类 (每次必须选且只能选一个)

* **`-c`** (Create): **创建**新的压缩包/归档文件。
* **`-x`** (Extract): **解压**归档文件。
* **`-t`** (List): **查看**归档文件里的内容（不解压）。

### 属性类

* **`-f`** (File): **指定文件名**。
    * ⚠️ **重要**：`-f` 必须是所有参数中的**最后一个**，因为它后面必须紧跟文件名。
    * ✅ 正确：`tar -cvf data.tar data/`
    * ❌ 错误：`tar -cfv data.tar data/` (这样系统会以为文件名叫 `v`)
* **`-v`** (Verbose): **显示详细过程**。会在屏幕上打印出正在处理的文件名。
* **`-C`** (Change directory): **指定解压路径**。

### 压缩格式类 (可选，不加就是只打包不压缩)

* **`-z`**: 使用 **gzip** 属性 (最常用，速度快，后缀 `.tar.gz` 或 `.tgz`)。
* **`-j`**: 使用 **bzip2** 属性 (压缩率更高，但慢，后缀 `.tar.bz2`)。
* **`-J`**: 使用 **xz** 属性 (压缩率极高，压缩非常慢，后缀 `.tar.xz`)。

## 2. 实战场景：压缩 (打包)

### 场景 1：最常用的 gzip 压缩 (.tar.gz)

这是 Linux 下最常见的压缩格式，兼顾了速度和压缩率。

```bash
# 语法：tar -czvf [压缩包名] [要打包的目录或文件]
tar -czvf project.tar.gz project/
```

* `c`: 创建
* `z`: 用 gzip 压缩
* `v`: 显示过程
* `f`: 指定文件名

### 场景 2：更高的压缩率 bzip2 (.tar.bz2)

如果你不在意时间，只想文件更小一点。

```bash
tar -cjvf project.tar.bz2 project/
```

### 场景 3：仅打包，不压缩 (.tar)

通常用于只是想把一堆文件变成一个文件，方便传输，不消耗 CPU 进行压缩。

```bash
tar -cvf project.tar project/
```

## 3. 实战场景：解压

### 场景 1：解压到当前目录

现代 `tar` 命令非常智能，通常不需要指定 `-z` 或 `-j`，它会自动识别格式。但为了规范，通常还是会加上。

```bash
# 解压 .tar.gz
tar -xzvf project.tar.gz

# 解压 .tar.bz2
tar -xjvf project.tar.bz2

# 万能解压 (让 tar 自己识别)
tar -xvf project.tar.xz
```

### 场景 2：解压到指定目录 (-C)

**这是新手最容易报错的地方**。如果你想把文件解压到 `/opt/app`，该目录必须先存在。

```bash
mkdir -p /opt/app
# 注意 -C 是大写，后面跟目标路径
tar -xzvf project.tar.gz -C /opt/app
```

### 场景 3：只解压压缩包中的某一个文件

假设你只想要包里的 `config.yaml`，不需要解压整个 10GB 的数据包。

```bash
# 语法：tar -xvf [压缩包] [包内文件的路径]
tar -xzvf project.tar.gz project/config/config.yaml
```

## 4. 实战场景：查看内容 (不解压)

在解压一个巨大的包之前，最好先看看里面有什么，或者确认一下它是带目录打包的，还是文件散落在根目录的。

```bash
# -t 参数用于 list
tar -tvf project.tar.gz
```

## 5. 高级技巧

### 排除特定文件 (--exclude)

打包整个项目，但不想包含 `.git` 目录或临时的 `log` 文件。

```bash
# 注意 --exclude 要放在文件名之前或最后，不能放在目录路径中间
tar -czvf code.tar.gz --exclude=.git --exclude=*.log project/
```

### 权限保留 (默认行为)

* **普通用户**：解压时，文件的拥有者会变成当前用户。
* **root 用户**：解压时，`tar` 会尝试**保留文件原本的用户和组信息**（如果系统里有对应的用户 ID）。
* 如果要强制 root 解压时也变成 root 拥有，可以使用 `--no-same-owner`。

## 6. 总结速查表

| 目的 | 命令组合 | 记忆口诀 |
| :--- | :--- | :--- |
| **打包压缩 (gzip)** | `tar -czvf file.tar.gz dir` | **C**reate **Z**ip **V**erbose **F**ile |
| **解压 (gzip)** | `tar -xzvf file.tar.gz` | e**X**tract **Z**ip **V**erbose **F**ile |
| **解压到目录** | `tar -xzvf file.tgz -C /dir` | \-**C**hange directory |
| **查看内容** | `tar -tvf file.tar.gz` | lis**T** **V**erbose **F**ile |
| **极限压缩 (xz)** | `tar -cJvf file.tar.xz dir` | 大写 **J** 对应高压缩 |

# Linux 环境变量命令详解

环境变量 (Environment Variables) 是系统或用户预先定义的一些参数。它们就像是系统的“全局变量”，告诉程序该去哪里找命令、当前是谁在登录、语言是什么等等。

## 1. 查看环境变量

最常用的查看命令有以下三个：

### 1.1 查看所有变量
```bash
# 显示当前所有的环境变量
env

# 或者使用 printenv (效果基本一样)
printenv
```

### 1.2 查看特定变量
如果你只想看某一个具体的变量（比如 PATH），使用 `echo` 配合 `$` 符号。

```bash
# 查看 PATH 变量
echo $PATH

# 查看当前用户
echo $USER

# 查看当前使用的 Shell
echo $SHELL
```

## 2. 设置/修改环境变量 (临时)

使用 `export` 命令设置的变量是**临时的**。
**生效范围**：仅在当前终端窗口有效。一旦关闭窗口或断开 SSH 连接，变量就会失效。

```bash
# 语法：export 变量名=值
# 注意：等号两边不能有空格！

# 例子：定义一个叫 MY_NAME 的变量
export MY_NAME="Jerry"

# 验证
echo $MY_NAME
```

## 3. 设置环境变量 (永久)

想要重启后依然有效，必须把 `export` 命令写入配置文件中。

### 3.1 对当前用户永久有效 (最常用)
修改用户主目录下的 `~/.bashrc` (如果你用的是 Bash) 或 `~/.zshrc` (如果你用的是 Zsh)。

1.  打开配置文件：
    ```bash
    vim ~/.bashrc
    ```
2.  在文件末尾添加：
    ```bash
    export MY_NAME="Jerry"
    ```
3.  保存退出，并**让配置立即生效**：
    ```bash
    source ~/.bashrc
    ```

### 3.2 对所有用户永久有效 (慎用)
修改系统级配置文件 `/etc/profile`。

1.  需要 root 权限：
    ```bash
    sudo vim /etc/profile
    ```
2.  在末尾添加 export 语句。
3.  `source /etc/profile` 使其生效。

## 4. 核心变量：PATH (重中之重)

`PATH` 是最著名的环境变量。它是一串目录的列表，中间用冒号 `:` 隔开。
当你输入一个命令（如 `ls` 或 `python`）时，系统会按顺序去这些目录里找对应的可执行文件。

### 查看 PATH
```bash
echo $PATH
# 输出示例：/usr/local/bin:/usr/bin:/bin:/usr/sbin
```

### 往 PATH 里添加新目录 (追加)
假设你安装了一个软件在 `/opt/myapp/bin`，你想直接运行里面的命令，不需要输全路径。

**临时添加：**
```bash
# 重点：$PATH 必须放在后面，表示“保留原有内容，加上新内容”
export PATH=/opt/myapp/bin:$PATH
```

**永久添加：**
在 `~/.bashrc` 文件末尾加入上面那行 `export` 代码，然后 `source ~/.bashrc`。

## 5. 删除/取消环境变量

如果你定义错了，或者想删除一个变量，使用 `unset`。

```bash
# 删除 MY_NAME 变量
unset MY_NAME
```

## 6. 总结速查表

| 操作 | 命令 | 说明 |
| :--- | :--- | :--- |
| **查看某个变量** | `echo $VAR` | 记得加 $ 符号 |
| **查看所有** | `env` | 列出所有环境变量 |
| **临时设置** | `export NAME="Val"` | 关掉终端就没了 |
| **永久设置** | 写入 `~/.bashrc` | 修改后记得 `source` |
| **追加 PATH** | `export PATH=新路径:$PATH` | 把新路径加到最前面 |
| **删除变量** | `unset NAME` | 移除变量 |

# Linux find 命令全攻略

`find` 是 Linux 系统中最强大的文件搜索工具。与 `locate`（查数据库，快但不准）不同，`find` 会**实时遍历文件系统**，虽然速度稍慢，但功能极其强大，支持按名称、大小、时间、权限甚至所有者进行搜索。

## 1. 核心语法

```bash
find [搜索路径] [匹配条件] [执行动作]
```

* **搜索路径**: 从哪里开始找（如 `/home`, `.` 当前目录, `/` 根目录）。
* **匹配条件**: 找什么样的文件（名字、大小、时间...）。
* **执行动作**: 找到后做什么（打印、删除、移动...，默认是打印）。

## 2. 常用搜索条件

### 2.1 按文件名搜索 (-name)

这是最常用的功能。

```bash
# 在当前目录及子目录中查找名为 config.yaml 的文件
find . -name "config.yaml"

# 忽略大小写查找 (-iname)
find . -iname "config.yaml"

# 使用通配符查找所有 .log 结尾的文件 (注意加引号，防止Shell提前扩展)
find /var/log -name "*.log"
```

### 2.2 按文件类型搜索 (-type)

如果你只想找目录，或者只想找普通文件。

```bash
# 只找目录 (directory)
find . -type d -name "backup"

# 只找普通文件 (file)
find . -type f -name "run.sh"
```

* `f`: 普通文件
* `d`: 目录
* `l`: 软链接

### 2.3 按文件大小搜索 (-size)

非常适合用来清理磁盘空间。

```bash
# 查找大于 100MB 的文件
find / -size +100M

# 查找小于 10KB 的文件
find . -size -10k

# 查找正好等于 1GB 的文件
find . -size 1G
```

* `k`: KB
* `M`: MB
* `G`: GB

### 2.4 按时间搜索 (-mtime)

运维排查问题的神器。

* `-mtime`: 修改内容的时间 (Modified time)
* `-atime`: 访问时间 (Accessed time)
* `-ctime`: 修改属性的时间 (Changed time)

**时间单位计算（以天为单位）：**

* `-7`: 最近 7 天**以内**（新文件）
* `+7`: 超过 7 天**以前**（老文件）
* `7`: 正好在第 7 天

```bash
# 查找最近 24 小时内被修改过的文件
find . -mtime -1

# 查找 30 天以前的老日志文件
find /var/log -mtime +30
```

## 3. 进阶：找到文件后执行操作 (-exec)

默认情况下，`find` 只是把结果打印出来。如果你想对找到的文件进行操作（比如复制、删除、重命名），需要用到 `-exec`。

### 语法结构

```bash
-exec 命令 {} \;
```

* `{}`: 这是一个占位符，代表 `find` 找到的每一个文件名。
* `\;`: 命令的结束符号（注意反斜杠和分号是必须的）。

### 实战示例

**场景 1：找到并删除**

```bash
# 找到所有 .tmp 结尾的文件并删除
find . -name "*.tmp" -exec rm -f {} \;

# 更简单的删除写法 (现代 find 支持)
find . -name "*.tmp" -delete
```

**场景 2：找到并复制**

```bash
# 把所有 jpg 图片复制到 /backup 目录
find . -name "*.jpg" -exec cp {} /backup/ \;
```

**场景 3：修改权限**

```bash
# 把所有 .sh 脚本加上可执行权限
find . -name "*.sh" -exec chmod +x {} \;
```

## 4. 逻辑运算符 (与/或/非)

你可以组合多个条件。

* **-a (and)**: 默认就是与逻辑，可以省略。
* **-o (or)**: 或者。
* **! (not)**: 非。

```bash
# 查找大于 100M 并且 是 .log 结尾的文件
find . -size +100M -name "*.log"

# 查找属于 user1 或者 属于 user2 的文件
find . -user user1 -o -user user2

# 查找当前目录下的文件，但排除 .git 目录
# (注意：-prune 是剪枝，比较复杂，排除目录通常用下面这种逻辑)
find . -path "./.git" -prune -o -print
```

## 5. 总结速查表

| 功能 | 参数 | 示例 |
| :--- | :--- | :--- |
| **按名字** | `-name` | `find . -name "*.txt"` |
| **忽略大小写** | `-iname` | `find . -iname "READme"` |
| **按类型** | `-type` | `f`(文件), `d`(目录), `l`(链接) |
| **按大小** | `-size` | `+100M` (大于), `-10k` (小于) |
| **按时间** | `-mtime` | `-7` (7天内), `+30` (30天前) |
| **深度限制** | `-maxdepth` | `find . -maxdepth 2 -name "*"` |
| **执行命令** | `-exec` | `-exec rm {} \;` |
`

# Linux 脚本解释器与 Shebang (`#!`) 详解

在 Linux 中，脚本（Script）本质上是一个纯文本文件。要让系统知道这个文本文件是用什么语言写的（Bash? Python? Node.js?），以及该用哪个程序来执行它，就需要用到**解释器 (Interpreter)** 和文件头部的 **Shebang**。

## 1. 什么是脚本解释器？

脚本语言（如 Shell, Python, Ruby）不需要像 C/C++ 那样预先编译成二进制文件。它们的代码由一个名为“解释器”的程序逐行读取并执行。

* **Shell 脚本** (`.sh`)：通常由 `/bin/bash` 或 `/bin/sh` 解释执行。
* **Python 脚本** (`.py`)：通常由 `/usr/bin/python3` 解释执行。

## 2. 核心机制：Shebang (`#!`)

在 Linux 脚本的第一行，通常会看到类似 `#!/bin/bash` 的字符。这被称为 **Shebang** (Hash-Bang)。

### 2.1 语法规则

```bash
#!<解释器的绝对路径> [可选参数]
```

* 必须在文件的**第一行**。
* 必须以 `#!` 开头。
* 后面紧跟解释器的**绝对路径**。

### 2.2 工作原理

当你在终端执行一个脚本（例如 `./myscript.sh`）时，Linux 内核会做以下动作：
1.  打开文件，读取**第一行**。
2.  发现前两个字节是 `#!`。
3.  读取 `#!` 后面的路径（例如 `/bin/bash`）。
4.  内核启动 `/bin/bash` 程序，并将脚本文件的路径作为参数传递给它。

**本质上，执行 `./myscript.sh` 等同于系统自动帮你运行了：**

```bash
/bin/bash ./myscript.sh
```

## 3. 常见的解释器声明

### 3.1 Shell 脚本

```bash
#!/bin/bash
# 或者使用最古老标准的 sh (通常是软链接)
#!/bin/sh
```

### 3.2 Python 脚本

```python
#!/usr/bin/python3
# 或者
#!/usr/bin/env python3
```

### 3.3 Node.js 脚本

```javascript
#!/usr/bin/env node
```

## 4. 为什么要用 `/usr/bin/env`？

你经常会看到两种写法：
1.  **硬编码路径**：`#!/usr/bin/python3`
2.  **使用 env**：`#!/usr/bin/env python3` (**推荐**)

**区别在于可移植性**：
* **硬编码**：假设 Python 一定装在 `/usr/bin` 下。如果用户自定义安装了 Python 在 `/usr/local/bin` 或者使用了 Anaconda/Virtualenv 环境，硬编码路径可能会导致“找不到文件”。
* **使用 env**：`env` 程序会去系统的 `PATH` 环境变量中查找第一个名为 `python3` 的程序。这样无论 Python 装在哪里，只要在 PATH 里就能找到。

## 5. 两种执行方式的区别

理解解释器后，就能明白以下两种执行方式的本质区别：

### 方式 A：作为程序执行 (依赖 Shebang)

```bash
chmod +x script.py
./script.py
```

* **前提**：脚本必须有执行权限 (`x`)。
* **机制**：系统读取脚本第一行的 Shebang，自动调用对应的解释器。
* **常见错误**：如果第一行写错了（如 `#!/bin/rpyton`），系统会报错 `No such file or directory`。这个报错指的不是脚本找不到，而是**解释器找不到**。

### 方式 B：作为参数执行 (忽略 Shebang)

```bash
python3 script.py
```

* **前提**：脚本只需要有读权限 (`r`)，不需要执行权限。
* **机制**：你显式指定了用 `python3` 来跑。此时系统**完全忽略**脚本里的 Shebang。
* **特例**：哪怕脚本第一行写的是 `#!/bin/bash`，只要内容符合 Python 语法，你用 `python3 script.py` 依然能跑起来。

## 6. 总结

| 概念 | 说明 |
| :--- | :--- |
| **Shebang** | 脚本第一行的 `#!`，告诉内核用谁来执行。 |
| **推荐写法** | `#!/usr/bin/env <语言>` (如 `#!/usr/bin/env bash`) |
| **./script** | 需要 `chmod +x`，依赖 Shebang 找到解释器。 |
| **bash script** | 不需要 `+x`，忽略 Shebang，强制用指定程序执行。 |

# Linux 创建多级目录：mkdir -p 详解

在 Linux 中，最基础的创建目录命令是 `mkdir` (Make Directory)。

但是，如果你想直接创建一个深层目录（例如 `a/b/c/d`），默认情况下 `mkdir` 会报错，因为它要求父目录必须先存在。这时就需要用到 `-p` 参数。

## 1. 核心命令

```bash
mkdir -p [路径]
```

* **`-p` (--parents)**: 这是一个“家长”模式。
    * **自动创建父目录**：如果路径中的父目录不存在，系统会自动把它们建立起来。
    * **静默模式**：如果目录已经存在，它**不会报错**（这在写脚本时非常有用）。

## 2. 场景对比

### 场景：你想创建 `/opt/project/src/main`

**如果不加 -p (报错)**：
```bash
mkdir /opt/project/src/main
# 报错: mkdir: cannot create directory ‘/opt/project/src/main’: No such file or directory
# 原因: /opt/project/src 这个父目录不存在，所以无法在里面创建 main
```

**加上 -p (成功)**：
```bash
mkdir -p /opt/project/src/main
# 成功！
# 系统会自动先创建 /opt/project
# 然后创建 /opt/project/src
# 最后创建 /opt/project/src/main
```

## 3. 进阶技巧

### 3.1 显示创建过程 (-v)

如果你想亲眼看到它创建了哪些目录，可以加上 `-v` (verbose)。

```bash
mkdir -pv a/b/c
# 输出:
# mkdir: created directory 'a'
# mkdir: created directory 'a/b'
# mkdir: created directory 'a/b/c'
```

### 3.2 一次创建复杂的目录树 (配合花括号)

结合 Shell 的花括号扩展功能，可以在一行命令里创建出项目的标准结构。

```bash
# 一次性创建 src, bin, doc 三个子目录
mkdir -p project/{src,bin,doc}

# 更复杂的情况：在 src 下再创建 main 和 test
mkdir -p project/{src/{main,test},bin,doc}
```

## 4. 权限设置 (-m)

你也可以在创建目录的同时直接赋予权限，避免后续再敲 `chmod`。

```bash
# 创建目录并设定权限为 700 (仅自己可见)
mkdir -m 700 -p secret/folder
```

## 5. 总结

| 命令 | 作用 |
| :--- | :--- |
| `mkdir dir` | 创建单级目录（父目录必须存在） |
| **`mkdir -p dir/subdir`** | **创建多级目录**（推荐常驻用法） |
| `mkdir -pv dir/subdir` | 创建多级目录并显示过程 |
| `mkdir -m 777 dir` | 创建目录并指定权限 |

# Linux 查看文本前几行：head 命令详解

`head` 命令用于输出文件的开头部分。它是处理大型日志文件（如查看最新的报错信息，如果日志是倒序写的）或快速预览文件格式的神器。

## 1. 核心语法

```bash
head [选项] [文件]
```

* **默认行为**：如果不加任何参数，`head` 默认显示文件的**前 10 行**。

## 2. 常用场景

### 2.1 指定行数 (-n)

这是最常用的功能。你想看几行就指定几行。

```bash
# 查看前 5 行 (标准写法)
head -n 5 config.yaml

# 简写形式 (直接加数字，非常常用)
head -5 config.yaml
```

### 2.2 指定字节数 (-c)

如果你关注的不是行，而是文件头部的特定大小（比如检查二进制文件的文件头魔数）。

```bash
# 查看前 20 个字节
head -c 20 image.png
```

### 2.3 处理多个文件

`head` 可以一次性读取多个文件。它会在每个文件的输出前自动加上文件名作为标题。

```bash
head -n 3 file1.txt file2.txt

# 输出示例：
# ==> file1.txt <==
# line 1
# line 2
# line 3
#
# ==> file2.txt <==
# line A
# line B
# line C
```

**隐藏文件名 (-q)**：如果你不想看到 `==> file1.txt <==` 这种标题，可以使用 `-q` (quiet) 参数。

```bash
head -q -n 3 file1.txt file2.txt
```

## 3. 进阶技巧：配合管道符 (|)

`head` 经常接在其他命令后面，用来截取输出结果的前几名。

```bash
# 场景：查看占用 CPU 最高的 5 个进程
# ps aux: 列出所有进程
# sort -rn -k 3: 按第3列(CPU)倒序排列
# head -5: 只看前 5 个
ps aux | sort -rn -k 3 | head -5
```

## 4. 负数参数的神奇用法

在某些较新的 Linux 版本（如 Coreutils 8.x+）中，`-n` 可以接受负数。

* **`head -n -5 file.txt`**：这就不是“看前5行”了，意思是**显示除了最后 5 行之外的所有内容**。
    * 相当于：从头开始显示，一直显示到倒数第 5 行截止。

## 5. 总结速查表

| 命令 | 作用 |
| :--- | :--- |
| `head file` | 显示前 10 行 (默认) |
| **`head -n 5 file`** | **显示前 5 行** |
| `head -5 file` | 显示前 5 行 (简写) |
| `head -c 100 file` | 显示前 100 个字节 |
| `head -q file1 file2` | 查看多个文件且不显示文件名 |

# Linux 进程查看：ps 命令详解

`ps` (Process Status) 用于显示当前系统的进程状态。与 `top` (动态实时监控) 不同，`ps` 提供的是一份**静态快照**。

## 1. 核心流派与语法

`ps` 命令混用了多种 Unix 系统的语法，导致参数非常复杂。你只需要记住最常用的两种组合即可：

### 1.1 BSD 风格 (推荐，最常用)
**`ps aux`**
* 注意：这里**没有**减号 `-`。
* **a**: 显示所有用户的进程 (All)。
* **u**: 显示进程的用户/拥有者信息 (User)。
* **x**: 显示没有控制终端的进程 (通常是后台服务)。

### 1.2 System V 风格 (常用)
**`ps -ef`**
* 注意：这里**有**减号 `-`。
* **-e**: 显示所有进程 (Every)。
* **-f**: 显示完整格式 (Full format)。

## 2. ps aux 输出字段详解

运行 `ps aux` 后，你会看到类似这样的表头：

```text
USER   PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root     1  0.0  0.1 168660 13244 ?        Ss   Jan01   0:05 /sbin/init
jerry 1234  5.0  2.3 800200 45000 pts/0    R+   10:00   0:10 python script.py
```

| 字段 | 含义 | 说明 |
| :--- | :--- | :--- |
| **USER** | 用户名 | 谁启动的这个进程 |
| **PID** | 进程 ID | 进程的身份证号，杀进程 (`kill`) 时用 |
| **%CPU** | CPU 占用率 | 该进程占用了多少 CPU 资源 |
| **%MEM** | 内存占用率 | 该进程占用了多少物理内存 |
| **VSZ** | 虚拟内存 | Virtual Memory Size (KB)，程序申请的内存总量 |
| **RSS** | 常驻内存 | Resident Set Size (KB)，程序**实际**使用的物理内存 (更具参考价值) |
| **STAT** | 进程状态 | **重要** (见下文详解) |
| **START** | 启动时间 | 进程是什么时候开始跑的 |
| **TIME** | 运行时间 | 进程实际占用 CPU 的总时长 |
| **COMMAND** | 命令 | 启动该进程的具体命令和参数 |

### 关键：STAT 状态代码
* **R (Running)**: 正在运行或在队列中等待。
* **S (Sleeping)**: 睡眠中（大部分进程都在这个状态，等待事件触发）。
* **D (Disk Sleep)**: **不可中断睡眠**（通常是在等待 I/O，比如硬盘读写，kill 不掉）。
* **Z (Zombie)**: **僵尸进程**（进程已死，但父进程没给它收尸）。
* **T (Stopped)**: 停止/暂停状态（如被 Ctrl+Z 挂起）。
* **<**: 高优先级。
* **N**: 低优先级。
* **+**: 在前台运行。

## 3. 常用实战场景

### 3.1 查找特定进程 (配合 grep)
这是最常用的操作。

```bash
# 查找所有与 nginx 相关的进程
ps aux | grep nginx

# 排除 grep 自身 (一个小技巧)
ps aux | grep [n]ginx
```

### 3.2 按资源占用排序
想看谁把 CPU 或内存吃光了？

```bash
# 按 CPU 使用率降序排列 (--sort)
# -pcpu 表示倒序 (descending) cpu
ps aux --sort=-%cpu | head -5

# 按内存使用率降序排列
# -rss 表示倒序 rss (物理内存)
ps aux --sort=-rss | head -5
```

### 3.3 查看父子进程关系 (树状图)
虽然有 `pstree` 命令，但 `ps` 也可以做。

```bash
# -f 会显示 PPID (父进程ID)
ps -ef 

# 打印 ASCII 树状结构
ps -ejH
# 或者
ps axjf
```

### 3.4 自定义输出字段
如果你只关心 PID 和命令，不想看一大堆其他信息。

```bash
# -o (output) 指定字段
ps -eo pid,user,args

# 示例输出：
#   PID USER     COMMAND
#     1 root     /sbin/init
#  1234 jerry    bash
```

## 4. 总结速查表

| 目的 | 命令 | 记忆口诀 |
| :--- | :--- | :--- |
| **查看所有进程** | `ps aux` | **A**ll **U**ser e**X**tended |
| **标准格式查看** | `ps -ef` | **E**very **F**ull |
| **查特定进程** | `ps aux \| grep name` | 管道过滤 |
| **按 CPU 排序** | `ps aux --sort=-%cpu` | 减号表示倒序 |
| **按内存排序** | `ps aux --sort=-rss` | RSS 是真实内存 |
| **看进程树** | `ps axjf` | **F**orest (树林) |

# Linux 日志文件位置与详解

Linux 的日志文件主要集中在 **`/var/log`** 目录下。掌握这些文件的位置，是排查系统故障（如启动失败、SSH 连不上、服务报错）的第一步。

## 1. 核心系统日志 (最重要)

这两个文件记录了系统运行的大部分信息，包括内核消息、软件安装、服务启动报错等。

| 发行版 | 文件路径 | 说明 |
| :--- | :--- | :--- |
| **Ubuntu / Debian** | `/var/log/syslog` | **系统综合日志**。也就是“大杂烩”，什么都在里面。 |
| **CentOS / RHEL** | `/var/log/messages` | 同上，RedHat 系的系统综合日志。 |

> **排查技巧**：如果系统出了莫名其妙的问题，先 `tail -f /var/log/syslog` (或 messages) 看看有没有报错。

## 2. 安全与认证日志 (黑客攻防)

记录了所有涉及用户身份验证的操作，比如 SSH 登录、sudo 提权、添加用户等。

| 发行版 | 文件路径 | 说明 |
| :--- | :--- | :--- |
| **Ubuntu / Debian** | `/var/log/auth.log` | 记录登录成功/失败、sudo 操作。 |
| **CentOS / RHEL** | `/var/log/secure` | 同上，名字不同。 |

> **排查技巧**：如果你怀疑有人在暴力破解你的 SSH 密码，查看这个文件，你会看到大量的 `Failed password` 记录。

## 3. 其他常见日志文件

| 文件路径 | 作用 |
| :--- | :--- |
| `/var/log/dmesg` | **开机/内核缓冲日志**。记录了系统启动时硬件加载的情况（网卡、硬盘识别等）。可以用 `dmesg` 命令直接查看。 |
| `/var/log/boot.log` | **启动过程日志**。记录了开机过程中各个服务（Service）启动是 OK 还是 Failed。 |
| `/var/log/kern.log` | **内核日志**。专门记录 Kernel 产生的日志，通常用于排查硬件驱动或内核崩溃问题。 |
| `/var/log/cron` | **定时任务日志**。记录 `crontab` 定时任务的执行情况。 |
| `/var/log/wtmp` | **登录历史**。这是一个**二进制文件**，不能用 `cat` 看，必须用 `last` 命令查看（记录谁什么时候登录过）。 |
| `/var/log/btmp` | **失败登录历史**。二进制文件，必须用 `lastb` 查看（记录谁尝试登录但失败了）。 |

## 4. 应用程序日志

通常安装的第三方软件（如 Nginx, MySQL, Docker）会在 `/var/log` 下建立自己的子目录。

* **Nginx**: `/var/log/nginx/access.log` (访问日志), `/var/log/nginx/error.log` (错误日志)
* **Apache/Httpd**: `/var/log/apache2/` 或 `/var/log/httpd/`
* **MySQL/MariaDB**: `/var/log/mysql/` 或 `/var/log/mariadb/`

## 5. Systemd 时代的日志工具：journalctl

在现代 Linux（CentOS 7+, Ubuntu 16.04+）中，系统使用了 `systemd` 管理服务，日志也被集中管理在二进制格式中。

虽然 `/var/log` 下的文件依然存在，但使用 `journalctl` 命令查看日志往往更强大。

```bash
# 查看所有日志 (按时间倒序)
journalctl -r

# 查看某个服务的日志 (比如 sshd)
journalctl -u sshd

# 实时滚动查看 (类似 tail -f)
journalctl -f
```

## 6. 总结速查表

| 目的 | 文件 (Ubuntu) | 文件 (CentOS) |
| :--- | :--- | :--- |
| **系统报错/通用** | `/var/log/syslog` | `/var/log/messages` |
| **查 SSH/Sudo** | `/var/log/auth.log` | `/var/log/secure` |
| **查硬件/内核** | `/var/log/dmesg` | `/var/log/dmesg` |
| **查历史登录** | `last` 命令 | `last` 命令 |

# Linux 文件列出：ls 命令详解

`ls` (List) 命令用于列出目录内容。它是用户与文件系统交互的第一步。

## 1. 核心语法

```bash
ls [选项] [文件或目录]
```

* **不加参数**：列出当前目录下的文件（不含隐藏文件），按字母顺序排序。
* **指定目录**：`ls /etc` 列出指定目录的内容。

## 2. 必会的三大金刚 (-l, -a, -h)

这三个参数通常组合使用：`ls -lah`。

### 2.1 长格式显示 (-l)

**Long listing format**。显示文件的详细属性（权限、链接数、所有者、组、大小、时间、文件名）。

```bash
ls -l
# 输出示例：
# drwxr-xr-x 2 root root 4096 Jan 1 12:00 mydir
# -rw-r--r-- 1 user user  123 Jan 1 12:05 file.txt
```

### 2.2 显示隐藏文件 (-a)

**All**。在 Linux 中，以点 `.` 开头的文件是隐藏文件（如 `.bashrc`, `.git`）。默认 `ls` 看不到它们，必须加 `-a`。

```bash
ls -a
```

### 2.3 人类可读大小 (-h)

**Human-readable**。默认 `ls -l` 显示的文件大小单位是**字节 (Bytes)**，很难看懂（比如 `2543123`）。
加上 `-h` 后，会自动转换为 **KB, MB, GB**。

```bash
ls -lh
# 大小列会变成：2.5M, 1.2G 等
```

## 3. 排序与展示优化

当文件很多时，默认的字母排序可能不是你想要的。

### 3.1 按时间排序 (-t)

**Time**。按修改时间排序，**最新的文件排在最上面**。
* 常配合 `-l` 使用：`ls -lt`

### 3.2 逆序排序 (-r)

**Reverse**。反转排序结果。
* 场景：配合 `-t` 使用 `ls -ltr`。这样**最新的文件会显示在最下面**。在终端里，光标通常停在最下面，这样不需要滚屏就能看到最新生成的文件（运维最爱）。

### 3.3 按大小排序 (-S)

**Size**。按文件大小排序，大的排前面。
* 场景：清理磁盘空间时找大文件 `ls -lSh`。

## 4. 进阶参数 (老手须知)

### 4.1 只看目录本身 (-d)

如果你运行 `ls -l /etc`，它会列出 `/etc` 下面的几百个文件。如果你只想看 `/etc` 这个目录本身的权限和属性，需要加 `-d`。

```bash
ls -ld /etc
# 输出：drwxr-xr-x 128 root root 12288 Jan 1 12:00 /etc
```

### 4.2 显示 Inode 号 (-i)

**Inode** 是文件在磁盘上的唯一标识符。
* 场景：如果有两个文件名看起来一模一样（可能是乱码或特殊字符），或者想区分硬链接，用 `-i` 看 inode 号。

```bash
ls -i file.txt
# 输出：1234567 file.txt
```

### 4.3 递归显示 (-R)

**Recursive**。不仅列出当前目录，还会递归列出所有子目录的内容（类似 `tree` 命令，但格式不如 `tree` 直观）。

```bash
ls -R
```

### 4.4 完整时间格式 (--full-time)

默认 `ls -l` 显示的时间可能只精确到分钟，甚至如果是去年的文件只显示年份。
如果需要**精确到纳秒**的时间戳（用于排查并发问题），使用此参数。

```bash
ls -l --full-time
```

## 5. 颜色与别名

你可能发现 `ls` 输出是有颜色的：
* **蓝色**：目录
* **绿色**：可执行文件
* **红色**：压缩包
* **青色**：软链接

这是因为大多数发行版默认配置了别名（Alias）。你可以通过 `alias` 命令查看：

```bash
alias ll
# 通常输出：alias ll='ls -alF' 或 'ls -l'
```

这就是为什么大家习惯直接敲 `ll` 而不是 `ls -l`。

## 6. 总结速查表

| 常用组合 | 作用 | 记忆场景 |
| :--- | :--- | :--- |
| **`ls -lah`** | 显示所有文件、详细信息、可读大小 | 日常查看最常用 |
| **`ls -ltr`** | 按时间逆序（最新的在底部） | 检查刚刚生成的日志/文件 |
| **`ls -lSh`** | 按大小排序（大的在顶部） | 磁盘清理找大文件 |
| **`ls -d */`** | 只列出当前目录下的子目录 | 快速看结构 |
| **`ls -i`** | 显示 inode | 解决文件名乱码/硬链接问题 |

# Linux 网络状态查看：netstat 命令详解

`netstat` 主要用于查看系统的网络连接状态（谁连了我？我连了谁？）、监听端口（哪些服务开了？）以及路由表信息。

> **注意**：如果提示 `command not found`，你需要安装 `net-tools` 包（CentOS: `yum install net-tools` / Ubuntu: `apt install net-tools`）。

## 1. 核心参数速记 (tunlp)

`netstat` 的参数非常多，但最实用的组合只有一个：**`-tunlp`**。

| 参数 | 英文全称 | 含义 |
| :--- | :--- | :--- |
| **`-t`** | **TCP** | 显示 TCP 协议的连接 |
| **`-u`** | **UDP** | 显示 UDP 协议的连接 |
| **`-n`** | **Numeric** | **不解析域名**，直接显示 IP 和端口号（这样速度快，且结果清晰） |
| **`-l`** | **Listening** | 仅显示**正在监听**（等待连接）的端口 |
| **`-p`** | **Process** | 显示哪个**进程/程序**（PID）占用了这个端口（需要 root 权限） |
| **`-a`** | **All** | 显示所有状态的连接（包括监听中和已建立连接的） |

## 2. 最常用的实战组合

### 2.1 查看所有监听端口 (查端口占用)

这是排查“服务起没起来”或者“端口被谁占了”的标准动作。

```bash
# 查看所有 TCP/UDP 的监听端口，并显示进程名
netstat -tunlp
```

### 2.2 查看所有活动连接

如果你想看服务器当前跟谁建立了连接（不仅仅是监听），去掉 `-l`，加上 `-a`。

```bash
netstat -anp
```

### 2.3 查看路由表

相当于 `route -n` 命令。

```bash
netstat -rn
```

### 2.4 查看网卡统计信息

查看数据包发送/接收的数量，以及是否有丢包（RX-ERR/TX-ERR）。

```bash
netstat -i
```

## 3. 输出字段详解

运行 `netstat -tunlp` 后，通常会看到如下输出：

```text
Proto Recv-Q Send-Q Local Address           Foreign Address         State       PID/Program name
tcp        0      0 0.0.0.0:80              0.0.0.0:* LISTEN      1234/nginx: master
tcp        0      0 192.168.1.10:22         10.0.0.5:54321          ESTABLISHED 999/sshd: root@pts
```

| 字段 | 含义 | 关键点 |
| :--- | :--- | :--- |
| **Proto** | 协议 | tcp, tcp6, udp |
| **Recv-Q** | 接收队列 | **重要**。表示收到了但程序还没来得及处理的数据字节数。如果这个值长期不为 0，说明**程序处理不过来了**（性能瓶颈）。 |
| **Send-Q** | 发送队列 | **重要**。表示对方还没签收（ACK）的数据字节数。如果这个值长期不为 0，说明**网络拥堵**或对方处理慢。 |
| **Local Address** | 本地地址 | 本机的 IP 和端口。`0.0.0.0:80` 表示监听所有网卡的 80 端口。 |
| **Foreign Address**| 外部地址 | 对方的 IP 和端口。 |
| **State** | 连接状态 | 见下文详解。 |
| **PID/Program** | 进程信息 | 哪个进程在用这个连接（需 root 权限才能看到所有）。 |

## 4. 关键 TCP 状态 (State)

排查网络问题时，状态栏是最重要的线索。

| 状态 | 含义 | 常见场景 |
| :--- | :--- | :--- |
| **LISTEN** | **监听中** | 服务启动正常，正在等待别人来连。 |
| **ESTABLISHED** | **已建立** | 连接成功，双方正在传输数据。 |
| **TIME_WAIT** | **等待关闭** | **主动关闭方**的状态。连接已断开，但系统保留该连接一小会儿（2MSL）以防数据残余。如果服务器上这个特别多，通常是短连接并发太高，需要优化内核参数。 |
| **CLOSE_WAIT** | **等待关闭** | **被动关闭方**的状态。对方发了 FIN（分手），但我还没发 ACK。如果这个特别多，说明**你的程序代码有 Bug**（忘了关闭连接）。 |
| **SYN_SENT** | **发送同步** | 我发起了连接请求，还没收到回复。通常意味着网络不通或对方防火墙拦截。 |

## 5. 进阶技巧：统计连接数

在高并发服务器上，我们经常需要统计有多少个连接处于 ESTABLISHED 状态，或者统计哪个 IP 连我最多。

```bash
# 统计各种状态的连接数
netstat -n | awk '/^tcp/ {++S[$NF]} END {for(a in S) print a, S[a]}'

# 输出示例：
# ESTABLISHED 500
# TIME_WAIT 120
# LISTEN 15
```

## 6. 接班人：ss 命令

虽然 `netstat` 很常用，但在连接数破万时，它会变得非常慢。现代 Linux 推荐使用 **`ss`** (Socket Statistics)。
* 参数几乎一样：`ss -tunlp`
* 速度快很多，且能显示更多 TCP 内部信息。

## 7. 总结速查表

| 目的 | 命令 | 记忆口诀 |
| :--- | :--- | :--- |
| **查端口占用 (最常用)** | `netstat -tunlp` | **TUNLP** (TCP, UDP, Numeric, Listen, Process) |
| **查路由表** | `netstat -rn` | **R**oute **N**umeric |
| **查网卡丢包** | `netstat -i` | **I**nterface |
| **统计连接数** | (配合 awk 使用) | 见进阶技巧 |

# Linux 软链接与硬链接详解

在 Linux 中，链接（Link）是一种让一个文件在多个位置可见的机制。理解链接的关键在于理解 **Inode**（索引节点）。

## 1. 核心概念：Inode

* **文件名**：只是给人类看的别名。
* **Inode**：文件在磁盘上的唯一标识（身份证号），记录了文件的权限、大小、数据块位置等属性。
* **数据块**：真正存数据的地方。

## 2. 硬链接 (Hard Link)

硬链接本质上是**同一个文件的不同名字**。

* **机制**：两个文件名指向**同一个 Inode**。
* **命令**：`ln 源文件 目标文件` (不加任何参数)。
* **特性**：
    * **实时同步**：修改其中一个，另一个也会变（因为它们就是同一个文件）。
    * **删除无忧**：删除源文件，硬链接依然有效（因为数据还在，只是少了一个名字）。只有当所有硬链接都被删除，数据才会被回收。
    * **Inode 相同**：使用 `ls -i` 查看，它们的 inode 号是一样的。
* **局限性**：
    * **不能跨分区**：硬链接不能跨越不同的文件系统。
    * **不能链接目录**：为了防止死循环，Linux 不允许给目录创建硬链接。

### 实战示例

```bash
# 创建硬链接
echo "Hello" > source.txt
ln source.txt hard_link.txt

# 查看 inode，发现是一样的
ls -li source.txt hard_link.txt
# 123456 -rw-r--r-- 2 root root 6 Jan 1 12:00 hard_link.txt
# 123456 -rw-r--r-- 2 root root 6 Jan 1 12:00 source.txt

# 删除源文件，硬链接依然能看
rm source.txt
cat hard_link.txt # 输出 Hello
```

## 3. 软链接 (Symbolic Link / Symlink)

软链接相当于 Windows 下的**快捷方式**。

* **机制**：软链接是一个**独立的文件**（有自己的 Inode），它的内容是**源文件的路径**。
* **命令**：`ln -s 源文件 目标文件` (**务必加 -s**)。
* **特性**：
    * **Inode 不同**：它是一个全新的文件。
    * **路径依赖**：如果源文件被移动或重命名，软链接会**失效**（变成死链，通常显示为红色闪烁）。
    * **万能**：可以跨分区，可以链接目录。
* **最佳实践**：创建软链接时，源文件最好写**绝对路径**，否则移动链接文件后容易失效。

### 实战示例

```bash
# 创建软链接
echo "World" > source.txt
ln -s /root/source.txt /tmp/soft_link.txt

# 查看属性，你会看到箭头指向
ls -l /tmp/soft_link.txt
# lrwxrwxrwx 1 root root 15 Jan 1 12:05 /tmp/soft_link.txt -> /root/source.txt

# 删除源文件，软链接失效
rm source.txt
cat /tmp/soft_link.txt # 报错: No such file or directory
```

## 4. 总结对比表 (面试必考)

| 特性 | 硬链接 (Hard Link) | 软链接 (Soft Link) |
| :--- | :--- | :--- |
| **命令** | `ln` | `ln -s` |
| **本质** | 同一个文件的别名 | 快捷方式 (存路径) |
| **Inode** | **相同** | **不同** |
| **跨分区** | 不可以 | **可以** |
| **链接目录** | 不可以 | **可以** |
| **源文件删除** | **依然可用** | **失效 (死链)** |
| **文件类型** | 普通文件 (`-`) | 链接文件 (`l`) |

## 5. 什么时候用哪个？

* **软链接**：**90% 的场景都用这个**。比如配置 Nginx 站点、安装软件版本切换（如 `python -> python3.8`）、快捷访问深层目录。
* **硬链接**：主要用于**备份**和**快照**场景。比如防止重要文件被误删（只要还有一个硬链接在，文件就在），或者节省磁盘空间的增量备份。

# Linux 内存监控：free 命令详解

`free` 命令用于显示系统当前的内存状态，包括物理内存、Swap 交换分区以及内核缓冲区/缓存的使用情况。

## 1. 核心用法

最常用的组合只有一个：**`-h`** (Human Readable)。

```bash
free -h
```

如果你需要持续监控（例如压测时），可以配合 `-s` 或 `watch`：

```bash
# 每秒刷新一次
free -h -s 1

# 或者用 watch (推荐，界面更稳)
watch -n 1 free -h
```

## 2. 输出字段深度解析

在 CentOS 7+ / Ubuntu 16.04+ 等现代系统中，`free -h` 的输出如下：

```text
              total        used        free      shared  buff/cache   available
Mem:           15Gi       4.5Gi       2.1Gi       1.2Gi       8.9Gi        10Gi
Swap:         2.0Gi          0B       2.0Gi
```

### 第一行：物理内存 (Mem)

这是最容易产生误解的地方，尤其是 `free` 和 `available` 的区别。

| 字段 | 含义 | 深度解读 |
| :--- | :--- | :--- |
| **total** | 总内存 | 物理内存总大小（通常比硬件标称略小，因为内核保留了一部分）。 |
| **used** | 已用内存 | **计算公式**：`total - free - buff/cache`。<br>这是被进程真正“独占”的内存。 |
| **free** | 空闲内存 | **未被任何用途占用**的内存。<br>⚠️ **注意**：Linux 会尽可能利用内存做缓存，所以这个值通常很小，但这**不代表**内存不够用。 |
| **shared** | 共享内存 | `tmpfs` (内存文件系统) 使用的内存。这部分内存被计入 `used`，但也算在 `buff/cache` 里。 |
| **buff/cache** | 缓冲/缓存 | **核心指标**。<br>**Buffers**: 存放文件系统的元数据（如目录结构、权限）。<br>**Cache**: 存放文件内容（Page Cache）。<br>**特性**：这部分内存是可以被**瞬间释放**的。当应用程序需要内存时，系统会优先回收这里。 |
| **available** | **可用内存** | **这是判断内存够不够用的唯一标准**。<br>它估算了在不进行 Swap 的情况下，还可以启动多少新程序。约等于 `free + (buff/cache - 不可回收部分)`。 |

### 第二行：交换分区 (Swap)

| 字段 | 含义 |
| :--- | :--- |
| **Swap** | 硬盘上的虚拟内存。 |
| **used** | 如果这个值**大于 0 且不断增长**，说明物理内存真的不够用了，系统开始变慢（Thrashing）。 |

## 3. 常见误区：Linux 吃内存？

**误区**：看到 `free` 很小（比如几百 MB），觉得系统要崩了。
**真相**：
1.  Linux 的哲学是 **"Unused RAM is wasted RAM"**（不用的内存是浪费）。
2.  系统会自动把读取过的文件放入 `buff/cache`，以便下次读取时加速（IO 优化）。
3.  **只要 `available` 还很大，系统就是健康的。**
4.  只有当 `available` 很低，且 Swap 的 `used` 开始飙升时，才是真正的内存不足 (OOM 风险)。

## 4. 进阶参数

* **`-w` (Wide)**: 宽模式输出。
    * 在老版本 `free` 中，Buffer 和 Cache 是合并显示的。使用 `-w` 可以将它们分开显示（如果内核支持）。
    * `free -w -h`

* **`-c` (Count)**: 刷新几次后自动退出。
    * `free -h -s 1 -c 5` (每秒一次，执行 5 次后结束)。

## 5. 手动释放缓存 (仅限测试)

在生产环境**严禁**随意执行此操作，这会导致瞬间 IO 飙升。但在测试程序真实内存占用时可能用到：

```bash
# 释放 PageCache, dentries 和 inodes
echo 3 > /proc/sys/vm/drop_caches
```

执行后，你会发现 `buff/cache` 瞬间变小，`free` 瞬间变大，但系统运行速度可能会短暂变慢。

# Linux 网络新贵：ss 命令详解

`ss` (Socket Statistics) 是 `netstat` 的现代替代品。它不仅显示更多信息，而且在处理大量连接（如高并发 Web 服务器）时，速度比 `netstat` 快得多。

## 1. 为什么弃用 netstat？

* **速度**：`netstat` 读取 `/proc/net/tcp`，连接多了读取极慢。`ss` 直接通过 Netlink 与内核通信，速度极快。
* **功能**：`ss` 支持更强大的过滤器（Filter）。

## 2. 核心参数速记 (tunlp)

好消息是，`ss` 沿用了 `netstat` 的大部分参数习惯，你可以继续使用 **`-tunlp`**。

| 参数 | 英文全称 | 含义 |
| :--- | :--- | :--- |
| **`-t`** | **TCP** | 显示 TCP 连接 |
| **`-u`** | **UDP** | 显示 UDP 连接 |
| **`-n`** | **Numeric** | 不解析域名 (显式 IP) |
| **`-l`** | **Listening** | 仅显示监听端口 |
| **`-p`** | **Process** | 显示进程信息 (需 root) |
| **`-a`** | **All** | 显示所有 (监听 + 已建立) |
| **`-s`** | **Summary** | **摘要统计** (netstat 没有这个，非常好用) |

## 3. 常用实战场景

### 3.1 查看监听端口 (最常用)

检查服务器开了哪些端口。

```bash
# -t: TCP, -n: 数字, -l: 监听, -p: 进程
ss -tnlp
```

### 3.2 快速查看连接统计 (-s)

这是 `ss` 的一大亮点。它不列出具体连接，只告诉你当前有多少个 TCP 连接、多少个 UDP 连接。**排查服务器负载时，第一步应该敲这个**。

```bash
ss -s

# 输出示例：
# Total: 1000
# TCP:   500 (estab 400, closed 50, orphaned 0, timewait 50)
```

### 3.3 查看所有已建立的连接

去掉 `-l` 即可。

```bash
ss -tnp
```

## 4. 杀手级功能：高级过滤

`netstat` 只能 grep，而 `ss` 自带强大的过滤语法，效率更高。

### 4.1 按状态过滤

只看处于 `ESTABLISHED` (已建立) 状态的连接。

```bash
ss -t state established
# 或者只看 TIME-WAIT
ss -t state time-wait
```

### 4.2 按 IP 和端口过滤

这是 `ss` 最强大的地方。

```bash
# 1. 查找所有连接到本机 22 端口 (SSH) 的连接
ss -tn dst :22

# 2. 查找本机连出去到 8.8.8.8 的连接
ss -tn dst 8.8.8.8

# 3. 查找源端口大于 1024 的连接
ss -tn sport > :1024

# 4. 复杂组合：查找目标端口是 80 或 443 的连接
ss -tn '( dport = :80 or dport = :443 )'
```

## 5. 性能对比

在连接数达到 10,000+ 的服务器上：
* `netstat`：可能会卡顿 10秒 甚至更久。
* `ss`：通常在 0.1秒 内返回结果。

## 6. 总结

* **习惯**：尽快把手指肌肉记忆从 `netstat` 切换到 `ss`。
* **常用**：`ss -tnlp` (查端口), `ss -s` (查概况)。
* **进阶**：使用 `dst`, `dport` 进行精确过滤。

# 虚拟机网络模式详解：桥接、NAT 与 仅主机

在使用 VMware Workstation、VirtualBox 或 KVM 等虚拟化软件运行 Linux 时，网络模式的选择决定了虚拟机能否上网、能否被局域网访问。

可以将这三种模式简单理解为：**独立个体（桥接）**、**寄生（NAT）** 和 **闭门造车（仅主机）**。

## 1. 桥接模式 (Bridged)

**“我是一个独立的个体”**

* **原理**：虚拟网卡通过虚拟网桥，直接“搭桥”连接到宿主机的物理网卡上。在路由器看来，**虚拟机和宿主机是两台完全独立的电脑**，地位是平等的。
* **IP 特征**：虚拟机 IP 与宿主机 IP 在**同一个网段**。
    * 宿主机：`192.168.1.5`
    * 虚拟机：`192.168.1.6` (直接从路由器 DHCP 获取)
* **连通性**：
    * 虚拟机 <-> 互联网：✅ (只要宿主机能上，它就能上)
    * 虚拟机 <-> 宿主机：✅
    * 虚拟机 <-> 局域网其他电脑：✅
* **适用场景**：
    * 你需要把虚拟机当成一台真实的服务器，供局域网内的其他人访问（比如搭建 Web 服务器给同事用）。
* **缺点**：
    * 占用局域网 IP 资源。
    * 受物理网络环境影响大。如果你带着笔记本从公司（固定IP）回到家（DHCP），虚拟机的 IP 设置可能需要跟着改，否则无法上网。
    * 某些校园网或公司内网绑定 MAC 地址，可能会阻断桥接模式。

## 2. NAT 模式 (Network Address Translation)

**“我躲在宿主机身后”**

* **原理**：虚拟机没有“独立身份”，它躲在宿主机后面。宿主机充当了虚拟机的“路由器”和“NAT网关”。
    * 虚拟机发出的数据包，会被宿主机转换地址（NAT）后发出去。
    * 外部网络（包括路由器）只知道宿主机的存在，完全不知道虚拟机的存在。
* **IP 特征**：虚拟机位于一个由虚拟化软件创建的**独立私有网段**。
    * 宿主机：`192.168.1.5` (物理网卡)
    * 虚拟机：`192.168.126.128` (虚拟 NAT 网卡分配)
* **连通性**：
    * 虚拟机 -> 互联网：✅ (通过宿主机转发)
    * 互联网 -> 虚拟机：❌ (默认拒绝，外部看不见虚拟机，除非做端口映射)
    * 宿主机 -> 虚拟机：✅ (通过 VMware Network Adapter VMnet8 通信)
* **适用场景**：
    * **最常用的模式**（默认推荐）。适合需要上网安装软件，但不需要被外部访问的场景。
    * **网络适应性强**。无论宿主机连的是公司 WiFi 还是手机热点，虚拟机的网络配置都不用变，依然能上网。

## 3. 仅主机模式 (Host-Only)

**“我们之间的小秘密”**

* **原理**：虚拟机被**断开**了与外部物理网络的连接，只连接到一个**封闭的虚拟交换机**上。这个虚拟网络里只有：虚拟机们 和 宿主机。
* **IP 特征**：完全独立的私有网段。
* **连通性**：
    * 虚拟机 <-> 互联网：❌ (**无法上网**)
    * 虚拟机 <-> 宿主机：✅ (通过 VMware Network Adapter VMnet1 通信)
* **适用场景**：
    * 需要一个绝对安全的内部环境，防止病毒感染或数据泄露。
    * 搭建复杂的内部集群测试（如 Kubernetes 实验、病毒分析），不需要外网干扰，也不希望干扰外网。

## 4. 总结速查表

| 模式 | 虚拟机地位 | 能否上网 | 局域网能否访问它 | IP 变动性 | 典型用途 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **桥接 (Bridged)** | 独立设备 | 能 | **能** | 随物理网络变化 | 对外提供服务的服务器 |
| **NAT** | 宿主机的子设备 | 能 | 否 | **稳定** | 个人学习、开发、安装软件 |
| **仅主机 (Host-Only)** | 隔离设备 | **否** | 否 | 稳定 | 内部测试、安全隔离 |

# Linux 防火墙王者：iptables 命令详解

`iptables` 不是一个服务，而是一个客户端工具，用于管理 Linux 内核中 `netfilter` 模块的安全规则。它通过“表”和“链”来组织规则，决定数据包是放行（ACCEPT）、丢弃（DROP）还是转发（FORWARD）。

## 1. 核心概念：四表五链

这是 `iptables` 最难理解也是最重要的部分。对于日常运维，你只需要关注 **"Filter 表"** 和 **"NAT 表"**。

### 1.1 "五链" (The 5 Chains)
链就是数据包流转过程中的关卡。

1.  **INPUT**: 任何**发往本机**的数据包，都要经过这道关（主要用于防守）。
2.  **OUTPUT**: 任何**从本机发出**的数据包，都要经过这道关（主要用于限制外连）。
3.  **FORWARD**: 任何**不进入本机，只是经过本机转发**的数据包（本机作为路由器时使用）。
4.  **PREROUTING**: 数据包**刚到达网卡**，路由判断之前（用于 DNAT，端口映射）。
5.  **POSTROUTING**: 数据包**即将离开网卡**，路由判断之后（用于 SNAT，让内网机器上网）。

### 1.2 "四表" (The 4 Tables)
表是存放规则的容器。

1.  **filter (默认表)**: 负责过滤（防火墙功能）。包含 `INPUT`, `OUTPUT`, `FORWARD`。
2.  **nat**: 负责网络地址转换。包含 `PREROUTING`, `POSTROUTING`, `OUTPUT`。
3.  *mangle*: 修改数据包（较少用）。
4.  *raw*: 其它高级功能（极少用）。

## 2. 核心语法结构

```bash
iptables -t [表名] [操作] [链名] [匹配条件] -j [动作]
```

* **-t 表名**: 默认为 `filter`，如果操作 NAT 需要指定 `-t nat`。
* **操作**: `-A` (追加), `-I` (插入), `-D` (删除), `-F` (清空), `-L` (查看)。
* **匹配条件**: `-p` (协议), `-s` (源IP), `-d` (目标IP), `--dport` (目标端口)。
* **-j 动作**:
    * **ACCEPT**: 允许通过。
    * **DROP**: 直接丢弃（对方不知道，表现为超时）。
    * **REJECT**: 拒绝并通过数据包通知对方（对方立刻知道被拒）。
    * **SNAT / DNAT / MASQUERADE**: 地址转换相关。

## 3. 常用实战命令

### 3.1 查看规则 (-L)

```bash
# 查看 filter 表的规则 (默认)
# -n: 不解析域名(快)，-v: 显示详细信息
iptables -L -n -v

# 查看 nat 表的规则
iptables -t nat -L -n -v

# 显示规则序号 (删除时很有用)
iptables -L -n --line-numbers
```

### 3.2 清空规则 (-F)

**⚠️ 高危操作**：如果你是远程 SSH 连接，且默认策略是 DROP，执行这个可能会把你锁在外面！

```bash
# 清空 filter 表
iptables -F
# 清空 nat 表
iptables -t nat -F
```

### 3.3 封禁与解封 (-A / -D)

```bash
# 1. 封禁特定 IP (如 192.168.1.100)
# -A INPUT: 追加到 INPUT 链末尾
# -s: source (源地址)
# -j DROP: 丢弃
iptables -A INPUT -s 192.168.1.100 -j DROP

# 2. 封禁特定端口 (如禁止外部访问本机的 8080)
iptables -A INPUT -p tcp --dport 8080 -j DROP

# 3. 删除规则 (按序号)
# 先查序号：iptables -L -n --line-numbers
# 删除 INPUT 链的第 1 条规则
iptables -D INPUT 1
```

### 3.4 开放端口 (白名单模式)

通常服务器的防火墙策略是“默认拒绝所有，只开放特定端口”。

```bash
# 1. 允许 SSH (22)
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 2. 允许 Web (80, 443)
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 3. 允许本机回环接口 (非常重要，否则本地服务互连会挂)
iptables -A INPUT -i lo -j ACCEPT
```

### 3.5 设置默认策略 (-P)

**⚠️ 极度高危**：一定要先配置好允许 SSH 的规则，再执行这一步，否则你会被立刻踢出服务器。

```bash
# 将 INPUT 链的默认策略设为 DROP (拒绝所有未明确允许的包)
iptables -P INPUT DROP
```

## 4. NAT 模式实战 (配合虚拟机网络)

如果你想把 Linux 当路由器用（比如让内网虚拟机通过宿主机上网），需要用到 SNAT。

```bash
# 开启内核转发功能
echo 1 > /proc/sys/net/ipv4/ip_forward

# 伪装上网 (Masquerade)
# 将所有来自 192.168.100.0/24 网段的数据包，伪装成 eth0 接口的 IP 发出去
iptables -t nat -A POSTROUTING -s 192.168.100.0/24 -o eth0 -j MASQUERADE
```

## 5. 规则的保存与恢复

`iptables` 命令生效是临时的，重启服务器后会消失。

* **CentOS 6 / 老系统**: `service iptables save`
* **通用方法 (iptables-save)**:
    ```bash
    # 保存到文件
    iptables-save > /etc/iptables.rules
    
    # 恢复规则
    iptables-restore < /etc/iptables.rules
    ```

## 6. 总结速查表

| 目的 | 命令示例 |
| :--- | :--- |
| **查看** | `iptables -L -n -v` |
| **封 IP** | `iptables -A INPUT -s 1.2.3.4 -j DROP` |
| **开端口** | `iptables -A INPUT -p tcp --dport 80 -j ACCEPT` |
| **删规则** | `iptables -D INPUT 1` (按序号) |
| **NAT上网**| `iptables -t nat -A POSTROUTING ... -j MASQUERADE` |

# 传统虚拟化 vs 容器技术：核心劣势解析

在云计算和 DevOps 时代，容器技术（如 Docker, Kubernetes）之所以能迅速取代传统虚拟化（如 VMware, KVM）的主导地位，主要归因于传统虚拟化在架构上的“笨重”。

## 1. 架构层面的根本区别

这是导致所有性能差异的根源。

* **传统虚拟化 (VM)**：
    * **Hypervisor 层**：必须有一层管理程序来模拟硬件。
    * **Guest OS (客户机操作系统)**：每个虚拟机都有自己**完整独立的操作系统内核**。哪怕你只是为了运行一个 10MB 的 Python 脚本，也得启动一个 2GB 大小的 Linux 系统。
* **容器技术 (Container)**：
    * **共享 Kernel**：所有容器**共享宿主机的操作系统内核**。
    * **进程级隔离**：容器本质上只是宿主机上的一个“被隔离的进程”。

## 2. 传统虚拟化的四大劣势

### 2.1 资源占用大 (Heavyweight)

* **虚拟机**：即使什么都不跑，光是启动 Guest OS 就需要占用几百 MB 甚至数 GB 的内存和大量的磁盘空间。一台宿主机跑 10 个虚拟机可能就吃力了。
* **容器**：没有独立的 OS，镜像通常只有几十 MB（Alpine Linux 甚至只有 5MB）。一台宿主机可以轻松运行成百上千个容器。

### 2.2 启动速度慢 (Slow Startup)

* **虚拟机**：启动需要经历完整的 BIOS 自检、Bootloader 加载、内核初始化、服务启动等过程，通常需要 **分钟级** 或 **数十秒**。
* **容器**：启动本质上只是启动一个进程，不需要引导 OS，通常只需要 **毫秒级** 或 **秒级**。这对于弹性伸缩（Auto-scaling）至关重要。

### 2.3 性能损耗 (Performance Overhead)

* **虚拟机**：指令需要经过 Hypervisor 层的翻译和调度，CPU、内存、I/O 都有额外的开销。
* **容器**：直接运行在宿主机内核上，**几乎没有性能损耗**（接近原生 Native 性能）。

### 2.4 交付与迁移困难 (Portability)

* **虚拟机**：迁移通常需要拷贝巨大的镜像文件（几十 GB）。且由于依赖底层的 Hypervisor 版本，容易出现“在我本地能跑，上线就崩”的环境一致性问题。
* **容器**：镜像分层存储，体积小，且包含了应用运行所需的所有依赖库（Library）。**"Build once, Run anywhere"** 彻底解决了环境一致性问题。

## 3. 总结对比表

| 特性 | 传统虚拟化 (VM) | 容器技术 (Container) |
| :--- | :--- | :--- |
| **隔离级别** | **硬件级隔离** (更安全，彻底独立) | **操作系统级隔离** (共享内核) |
| **操作系统** | 包含完整的 Guest OS | **不包含**，共享 Host Kernel |
| **启动时间** | 分钟级 / 秒级 | **毫秒级 / 秒级** |
| **存储占用** | GB 级别 | **MB 级别** |
| **性能损耗** | 有 Hypervisor 开销 | **接近原生** |
| **单机密度** | 低 (几十个) | **极高 (成百上千)** |

## 4. 为什么虚拟机还没死？

虽然容器优势巨大，但虚拟机依然不可替代，主要因为：
1.  **安全性**：VM 的隔离更彻底。如果容器攻破了共享内核，可能会波及整台机器，而攻破 VM 很难逃逸到宿主机。
2.  **多系统需求**：你不能在 Linux 宿主机的 Docker 里跑 Windows 容器（通常情况下），但 VM 可以。
3.  **混合部署**：现代云架构通常是 **"物理机 -> VM -> 容器"** 的嵌套模式（如 AWS EC2 上跑 K8s），结合了两者的优点。

# Linux 删除文件：rm 命令详解

`rm` (Remove) 用于删除文件或目录。

**⚠️以此为戒**：Linux 系统设计哲学是“默认用户知道自己在做什么”。当你敲下回车时，文件系统链接会被立即切断，数据极难恢复。

## 1. 核心语法

```bash
rm [选项] [文件或目录]
```

## 2. 必记的三大参数 (-r, -f, -i)

### 2.1 递归删除 (-r / -R)

**Recursive**。默认情况下，`rm` 只能删除文件，**不能删除目录**。
如果你要删除一个文件夹（以及里面所有的东西），必须加 `-r`。

```bash
rm -r my_folder/
```

### 2.2 强制删除 (-f)

**Force**。
* **特性 1**：不再询问确认（默认可能会问你“确定要删吗？”）。
* **特性 2**：如果文件不存在，也不报错，直接静默退出（写脚本时很有用）。

```bash
# 哪怕文件设有写保护，也强制删除，且不提示
rm -f protected_file.txt
```

### 2.3 交互模式 (-i)

**Interactive**。这是保命参数。在删除每个文件前都会询问你 `y/n`。

```bash
rm -i critical_config.conf
# 系统提示：rm: remove regular file 'critical_config.conf'?
```

## 3. 终极组合：rm -rf

这是 Linux 中最著名的命令组合，也是很多“删库跑路”事故的元凶。

* **含义**：**递归**且**强制**地删除指定路径下的所有内容，不给任何后悔机会。

```bash
# 删除当前目录下的 build 文件夹
rm -rf build/
```

### ⚠️ 灾难级命令：rm -rf /

试图删除根目录下的所有文件。
* 现代 Linux 发行版通常有 `--preserve-root` 保护机制，直接敲 `rm -rf /` 会被拒绝。
* 但是，如果你手滑敲成了 `rm -rf /*`（多了个星号），系统会认为你在通过通配符删除根目录下的所有子项，保护机制**无效**，系统会瞬间崩溃。

## 4. 实战场景与安全技巧

### 4.1 结合通配符

删除所有 `.log` 结尾的文件。

```bash
rm *.log
```

**安全技巧**：在使用通配符前，**先用 `ls` 看看选中了什么**。
* 先敲：`ls *.log` （确认一下是不是只想删这些）
* 再敲：`rm *.log`

### 4.2 删除以横杠 - 开头的文件

如果你有一个文件名叫 `-filename`，直接 `rm -filename` 会报错，因为系统把 `-f` 当成了参数。

**解决方法**：
```bash
# 方法 1：使用相对路径
rm ./-filename

# 方法 2：使用 -- 分隔符（表示参数结束）
rm -- -filename
```

### 4.3 为什么我没加 -i 它也问我？

很多发行版（如 CentOS, Ubuntu）为了安全，默认在 `.bashrc` 中设置了别名：
`alias rm='rm -i'`
这意味着你敲 `rm` 时，实际执行的是 `rm -i`。

**如何绕过别名？**
* 使用绝对路径：`/bin/rm file`
* 在命令前加反斜杠：`\rm file`

## 5. 总结速查表

| 命令 | 作用 | 危险等级 |
| :--- | :--- | :--- |
| `rm file` | 删除单个文件 | ⭐⭐ |
| `rm -f file` | 强制删除，不提示 | ⭐⭐⭐ |
| **`rm -r dir`** | **删除目录** | ⭐⭐⭐ |
| **`rm -rf dir`** | **强制删除目录 (最常用)** | ⭐⭐⭐⭐⭐ |
| `rm -i file` | 删除前询问 (最安全) | ⭐ |

# Linux 复制文件：cp 命令详解

`cp` (Copy) 命令用于将文件或目录从一个位置复制到另一个位置。

## 1. 核心语法

```bash
cp [选项] [源文件] [目标文件]
```

* **复制单个文件**：`cp file1.txt file2.txt` (把 file1 复制一份叫 file2)
* **复制到目录**：`cp file1.txt /tmp/` (把 file1 复制到 /tmp 目录下，保持原名)

## 2. 必会的核心参数 (-r, -p, -a)

### 2.1 递归复制目录 (-r / -R)

**Recursive**。这是新手最容易报错的地方。
默认 `cp` 只能复制文件。如果你尝试复制一个目录，必须加 `-r`。

```bash
# 错误写法：cp my_folder /tmp/ (报错：omitting directory)
# 正确写法：
cp -r my_folder /tmp/
```

### 2.2 保留文件属性 (-p)

**Preserve**。
默认情况下，`cp` 复制出来的文件，**所有者是当前用户，时间是当前时间**。
如果你想保留源文件的**修改时间、访问时间、所属组和权限**（这在备份配置文件时非常重要），请加 `-p`。

```bash
cp -p config.conf config.conf.bak
```

### 2.3 归档模式 (-a)

**Archive**。这是 `-p` 的终极增强版，等同于 `-dR --preserve=all`。
它会尽可能保留文件的一切属性（包括软链接本身而不是链接指向的文件、SELinux 上下文等）。**它是全盘备份时的首选参数。**

```bash
cp -a /var/www/html /backup/www/
```

## 3. 安全与智能复制 (-i, -u, -n)

### 3.1 交互模式 (-i)

**Interactive**。如果目标文件已经存在，`cp` 默认会直接覆盖它。
加上 `-i`，系统会先问你：“是否覆盖？”

```bash
cp -i file.txt existing_file.txt
# 提示：cp: overwrite 'existing_file.txt'?
```

### 3.2 增量/更新复制 (-u)

**Update**。这是一个非常实用的参数。
只有当**源文件比目标文件新**，或者**目标文件不存在**时，才进行复制。
这在同步两个大文件夹时非常有用，避免重复复制没变过的文件。

```bash
cp -ru source_dir/ target_dir/
```

### 3.3 不覆盖 (-n)

**No-clobber**。如果目标文件已存在，直接跳过，不覆盖，也不报错。

```bash
cp -n file.txt existing_file.txt
```

## 4. 常见坑点

### 4.1 目录斜杠的差异

这在 `rsync` 命令中区别很大，但在 `cp` 中区别较小，但仍需注意：
* `cp -r src dest`：如果 dest 存在，src 目录会成为 dest 的子目录 (`dest/src`)。
* `cp -r src/* dest`：把 src 下面的**内容**复制到 dest 里面。

### 4.2 覆盖只读文件

如果你是 root 用户，即使目标文件是“只读”的 (444)，`cp` 也会强制覆盖它。

## 5. 总结速查表

| 命令 | 作用 | 场景 |
| :--- | :--- | :--- |
| `cp file1 file2` | 简单复制 | 日常使用 |
| **`cp -r dir1 dir2`** | **复制目录** | 必会 |
| **`cp -a dir1 dir2`** | **完美克隆** | 系统备份/迁移 |
| `cp -p file1 file2` | 保留时间/权限 | 备份配置文件 |
| `cp -u dir1 dir2` | 仅复制新的 | 增量同步 |

# Linux 任务管理：fg 命令详解

在 Linux 中，我们经常需要同时处理多个任务。**`fg` (Foreground)** 命令的主要作用是将后台（Background）或暂停（Suspended）的作业调回到前台继续运行。

## 1. 核心场景：从暂停到恢复

这是最经典的用法，特别是在使用 `vim` 编辑文件或运行耗时脚本时。

### 第一步：暂停当前任务 (Ctrl + Z)

假设你正在用 `vim` 编辑代码，突然需要去终端执行一个 `ls` 命令，但又不想关闭 vim。
此时按下 **`Ctrl + Z`**：
* 系统会将 vim 进程**挂起 (Stopped)** 并放入后台。
* 你会重新回到 Shell 命令行。

```bash
[1]+  Stopped                 vim config.conf
```

### 第二步：查看后台任务 (jobs)

你可以使用 `jobs` 命令查看当前有哪些任务在后台。

```bash
jobs -l
# 输出示例：
# [1]+  1234 Stopped                 vim config.conf
# [2]-  5678 Running                 python script.py &
```
* **`[1]`**: 任务编号 (Job ID)，配合 `fg` 使用的关键数字。
* **`+`**: 表示这是“当前”任务（直接敲 `fg` 默认恢复它）。
* **`-`**: 表示这是“上一个”任务。

### 第三步：恢复到前台 (fg)

现在你想回到 vim 继续编辑。

```bash
# 语法：fg [任务编号]

# 方式 1：恢复最近的任务 (带 + 号的)
fg

# 方式 2：指定任务编号 (恢复 [1] 号任务)
fg %1
```

## 2. 关联命令：bg (Background)

如果你按 `Ctrl+Z` 暂停了一个正在下载大文件的命令，你希望它**继续运行**，但不要占用前台终端，这时应该用 `bg`。

* **`fg`**: 把任务拉回前台（你会再次看到它的界面或输出，且终端被占用）。
* **`bg`**: 让暂停的任务在后台**继续跑**（状态从 Stopped 变为 Running）。

```bash
# 1. 运行耗时命令
sleep 1000

# 2. 按 Ctrl+Z 暂停
# [1]+ Stopped sleep 1000

# 3. 让它在后台继续跑
bg %1
# [1]+ sleep 1000 & 
# (变成了 Running 状态)
```

## 3. 预备知识：& 符号

如果你一开始就知道这个命令要跑很久，可以直接在命令末尾加 `&`，让它直接在后台运行，就不用折腾 `Ctrl+Z` 了。

```bash
# 直接在后台运行脚本
python backup.py &
```

## 4. 总结速查表

| 操作 | 命令/快捷键 | 作用 |
| :--- | :--- | :--- |
| **暂停** | `Ctrl + Z` | 将前台进程挂起（暂停）并放入后台 |
| **查看** | `jobs` | 列出所有后台任务及其编号 |
| **恢复前台** | **`fg %n`** | **将后台任务 n 调回前台运行** |
| **后台运行** | `bg %n` | 让后台暂停的任务开始运行 |
| **起手后台** | `命令 &` | 直接让命令在后台启动 |

# Linux 磁盘空间查看：df 命令详解

`df` (Disk Free) 用于显示 Linux 系统中各文件系统的硬盘使用情况。它读取的是文件系统的超级块（Superblock）信息，所以速度极快。

## 1. 核心语法与常用组合

```bash
df [选项] [文件或目录]
```

### 必记参数 (-h, -T, -i)

| 参数 | 英文全称 | 作用 |
| :--- | :--- | :--- |
| **`-h`** | **Human-readable** | **最常用**。将字节自动转换为 **KB, MB, GB**，让人看得懂。 |
| **`-T`** | **Type** | 显示文件系统类型（如 `xfs`, `ext4`, `tmpfs`）。 |
| **`-i`** | **Inodes** | 查看 Inode 使用情况（排查“小文件过多”故障）。 |

**最佳实战组合**：
```bash
df -Th
# 同时显示：易读大小 + 文件系统类型
```

## 2. 输出字段深度解析

运行 `df -h` 后，你会看到如下表格：

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   30G   20G  60% /
devtmpfs        3.9G     0  3.9G   0% /dev
/dev/sdb1       100G   90G   10G  90% /data
```

| 字段 | 含义 | 关键点 |
| :--- | :--- | :--- |
| **Filesystem** | 文件系统 | 对应的物理分区（如 `/dev/sda1`）或逻辑卷。 |
| **Size** | 总容量 | 该分区的总大小。 |
| **Used** | 已用空间 | 已经存了多少数据。 |
| **Avail** | 可用空间 | **核心关注点**。还剩多少空间。 |
| **Use%** | 使用率 | **报警阈值**。通常超过 85% 或 90% 就需要运维介入清理了。 |
| **Mounted on** | 挂载点 | 该分区对应系统里的哪个目录（入口）。 |

## 3. 经典故障排查

### 3.1 磁盘明明有空间，但无法写入？(Inode 耗尽)

**现象**：`df -h` 显示磁盘才用了 50%，但创建文件报错 `No space left on device`。
**原因**：系统里有几十万个极小的文件（如缓存、session、邮件队列），把 **Inode**（身份证号资源）用光了。
**排查**：
```bash
df -i
# 如果 IUse% 达到 100%，说明是 Inode 耗尽。
```

### 3.2 删除了大文件，空间却没释放？

**现象**：你用 `rm` 删了一个 10GB 的 `access.log`，但 `df -h` 看到的可用空间完全没变。
**原因**：该文件正在被某个进程（如 Nginx）**打开/写入**。在 Linux 中，只要文件被进程占用，即便文件名没了，磁盘空间也不会释放。
**解决**：
1.  找到占用进程：`lsof | grep deleted`
2.  重启该进程（如 `systemctl reload nginx`）。
3.  **最佳实践**：以后清空日志不要用 `rm`，用重定向 `> access.log`，这样不需要重启进程。

## 4. df 与 du 的区别 (面试常问)

| 特性 | `df` (Disk Free) | `du` (Disk Usage) |
| :--- | :--- | :--- |
| **原理** | 读取文件系统元数据 (Superblock) | 逐个遍历文件累加大小 |
| **速度** | **极快** | 慢 (文件越多越慢) |
| **关注点** | **整个分区**的剩余情况 | **指定目录**的占用情况 |
| **准确性** | 包含被删除但未释放的空间 | 仅统计当前存在的文件 |

## 5. 总结

* **日常检查**：`df -h`
* **查分区类型**：`df -Th`
* **查 Inode**：`df -i`
* **空间释放**：如果不一致，记得检查是否有进程占用了已删除文件。

# Linux 文件句柄查看：lsof 命令详解

`lsof` (List Open Files) 用于列出当前系统打开文件的工具。在 Linux 中，一切皆文件（包括网络端口、硬件设备），因此 `lsof` 实际上是一个强大的系统监控工具。

> **提示**：如果是最小化安装的系统，可能没有这个命令，需要安装：`yum install lsof` 或 `apt install lsof`。

## 1. 核心语法与常用场景

**语法**：`lsof [选项] [文件或目录]`
**注意**：绝大多数情况需要 **root 权限** 才能看到完整的进程信息。

### 1.1 查谁在使用文件/目录 (最常用)

当你卸载挂载点 (`umount`) 失败提示 "Device is busy" 时，用这个查出凶手。

```bash
# 查看谁正在使用 /var/log/messages
lsof /var/log/messages

# 查看谁在 /home/jerry 目录下（包含子目录）
lsof +D /home/jerry
```

### 1.2 查端口占用 (替代 netstat)

`lsof` 查端口往往比 `netstat` 更直观。

```bash
# 查看谁占用了 80 端口
lsof -i :80

# 查看所有 TCP 连接
lsof -i tcp
```

### 1.3 查某个进程打开了哪些文件 (-p / -c)

排查某个进程为什么吃硬盘 IO，或者查看它加载了哪些库文件。

```bash
# 按 PID 查看
lsof -p 1234

# 按进程名查看 (如 nginx)
lsof -c nginx
```

### 1.4 查某个用户打开了哪些文件 (-u)

```bash
lsof -u root
# 排除 root 用户，看其他的 (^ 表示非)
lsof -u ^root
```

## 2. 输出字段深度解析 (难点)

运行 `lsof` 后，输出如下：

```text
COMMAND   PID USER   FD      TYPE DEVICE SIZE/OFF     NODE NAME
ssh       123 root  cwd       DIR  253,0     4096        2 /root
nginx     456 root  txt       REG  253,0  1234567   135790 /usr/sbin/nginx
node      789 user   3u      IPv4  12345      0t0      TCP *:3000 (LISTEN)
```

| 字段 | 含义 |
| :--- | :--- |
| **COMMAND** | 进程名 |
| **PID** | 进程 ID |
| **USER** | 用户 |
| **FD** | **文件描述符** (File Descriptor) - **关键点，见下表** |
| **TYPE** | **文件类型** - **关键点，见下表** |
| **DEVICE** | 磁盘设备号 |
| **SIZE/OFF** | 文件大小或偏移量 |
| **NAME** | 文件名、目录名或网络连接信息 |

### 2.1 详解 FD (文件描述符)

这是最容易让人困惑的一列。

| 代码 | 含义 | 说明 |
| :--- | :--- | :--- |
| **cwd** | Current Work Dir | 进程当前的**工作目录** |
| **txt** | Text | 程序代码段（即二进制可执行文件本身） |
| **mem** | Memory | 内存映射文件（如依赖的 `.so` 库） |
| **0u** | 0 + u (Read/Write) | 标准输入 (STDIN)，u 表示可读可写 |
| **1w** | 1 + w (Write) | 标准输出 (STDOUT)，w 表示只写 |
| **2w** | 2 + w (Write) | 标准错误 (STDERR) |
| **3r** | 3 + r (Read) | 自定义的第 3 号句柄，r 表示只读 |

### 2.2 详解 TYPE (文件类型)

| 代码 | 含义 |
| :--- | :--- |
| **DIR** | 目录 |
| **REG** | 普通文件 (Regular File) |
| **CHR** | 字符设备 (如终端) |
| **BLK** | 块设备 (如硬盘) |
| **IPv4/IPv6** | 网络套接字 (Socket) |
| **unix** | Unix 域套接字 (本机通信用) |

## 3. 高级黑魔法：恢复已删除文件

这是一个非常经典且实用的救援技巧。

**场景**：你误删除了一个重要的日志文件 `access.log`，但 Nginx 进程还在运行，且正抓着这个文件句柄没松手。
**原理**：只要进程还没关闭文件句柄，文件在磁盘上的数据块就不会真正被释放。我们可以通过 `/proc` 文件系统把它找回来。

**步骤**：

1.  **找到进程 PID 和 FD**：
    ```bash
    lsof | grep deleted
    # 输出示例：
    # nginx  1234  root  3w  REG  ...  access.log (deleted)
    ```
    这里 PID 是 `1234`，FD 是 `3w`（也就是 `3`）。

2.  **进入 /proc 目录**：
    在 Linux 中，进程打开的文件都会映射在 `/proc/PID/fd/FD_NUM`。
    ```bash
    ll /proc/1234/fd/3
    # 你会发现这就是那个被删的文件
    ```

3.  **恢复文件**：
    直接把这个句柄的内容拷贝出来。
    ```bash
    cp /proc/1234/fd/3 /var/log/access.log.recovered
    ```

## 4. 总结速查表

| 目的 | 命令示例 |
| :--- | :--- |
| **查端口** | `lsof -i :22` |
| **查文件占用** | `lsof /var/lib/mysql/ibdata1` |
| **查进程** | `lsof -p 1234` |
| **查用户** | `lsof -u jerry` |
| **查网络** | `lsof -i tcp` |
| **查已删除文件** | `lsof \| grep deleted` |
